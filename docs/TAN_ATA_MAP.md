# Карта переноса Tan Ata

## Граница проверки, 10 ноября 2026

Источник: Tan Ata, коммит `4822e213e991f6e8c0177751e0fd6626b1f237bc`.
Проверены каталог разговоров и связанные исходные страницы; пути остальных модулей
сверены с деревом этого коммита. Наличие исходника не доказывает работоспособность production.
Это инвентаризация для переноса, не аудит всех действий, API и прав доступа Tan Ata.
Никакие личные данные, ключи или production-сервисы для этой проверки не нужны.

Статус Pairspace сверён с исходным снимком `0f80e1631d19c575254ad2dfa8b941cb3ae1b555`.
Статусы относятся к мобильному продукту, а не к Next.js референсу или отдельным тестам API:
- **Работает локально**: конкретное действие в preview, без заявления о серверной интеграции.
- **Демо**: экран/образец существует, но реальный пользовательский сценарий не подключён.
- **План**: полноценной реализации нет; карточка «В разработке» не повышает этот статус.
- Все функции Tan Ata включены владельцем в план переноса 10 ноября 2026, включая
  астрологию и нумерологию. Приоритет определяет порядок, но не исключает функцию.
  Если дальнейший разбор выявит дополнительные сценарии, добавить их в карту.
  Перенос допускает улучшения под независимые пары, но не копирование личных данных.
Приоритеты ниже — очередь обсуждения переноса, не обещание даты или платного тарифа.

Работает локально: навигация и возврат, переключение RU/EN, вкладки образца календаря,
ввод и очистка RAM-черновика чата. Эти действия не сохраняют данные на сервере.
Сердце открывает только информационный alert, не отправляет «Думаю о тебе».
Основание: `apps/mobile/App.tsx`, `src/PreviewScreen.tsx`, `src/Showcase.tsx`
(пути `src/` здесь внутри `apps/mobile/`). Подробнее: [UI checkpoint](UI_PREVIEW_CHECKPOINT.md).

## Отдельные решения и расширения

- **План P2: астрология и нумерология**, включены решением владельца о полном переносе.
  Источники: `app/together/page.tsx`, `lib/astro.ts`, `lib/zodiac.ts`, `lib/matrix.ts`
  на том же исходном SHA. Это развлекательные интерпретации, не научная совместимость,
  диагностика, прогноз достоверных событий или основание для важных решений.
  До переноса: изоляция пар, добровольный минимальный ручной ввод, настройки видимости,
  удаление/отзыв; никаких автоматических импортов профилей, контактов или геолокации.
  Проверить отказ без потери основных функций, границы дат/поясов и воспроизводимость
  выбранного расчёта на синтетических данных. Точность алгоритма не доказывает истинность
  интерпретации. Астрономическую фазу Луны не смешивать с этими интерпретациями.
  Разделение Free/Plus открыто; рабочей мобильной реализации пока нет.
- **Демо: постоянный чат** — новое требование Pairspace, не перенос режима разговоров.
  Есть RAM-черновик; очередь и серверные use cases существуют отдельно, не подключены
  к UI. Это не работающая переписка между двумя устройствами. См. [CHAT.md](CHAT.md).
- **Демо / План: задачи, покупки, бюджет** — расширение Pairspace. Календарь показывает
  образцы планов/задач; реальные совместные списки и бюджет не подключены.
  Нужны версии, конфликты и прозрачный вклад обоих. См. [FINANCE.md](FINANCE.md).

## Запрещённый перенос

Общий код доступа, фиксированные две личности, production-ключи, дампы, персональные
тексты и изображения, Telegram chat IDs, исходная история Git и публичные URL приватных файлов.
Административная роль не должна определяться полом или исходным маршрутом `/him`.

## Порядок переноса и проверки

Исходный файл и SHA → лицензия/авторство → нейтрализация → чистая логика → ACL и новые
контракты → регрессия поведения → тесты двух пар → UI RU/EN → независимая приёмка.
Для всех строк нужны проверки пары A/B, бывшего участника, неавторизованного клиента,
повторов, offline/reconnect, изменения времени и фоновых заданий, где это применимо.
Нельзя скрыто заменить полноценный сценарий статичной карточкой или считать доменный
контракт доказательством работающего пользовательского сценария.

Для этой правки: проверены diff, ссылки на исходные пути и лимит 600 строк; код не менялся.
Unit/integration/native/E2E в рамках документальной правки не запускались. Приёмка
переноса каждого сценария остаётся отдельным этапом, текущая правка ещё не принята.
Связанные документы: [FOUNDATION.md](FOUNDATION.md), [ROADMAP.md](ROADMAP.md),
[QUALITY.md](QUALITY.md). Пробелы полной проверки исходников сохраняются до переноса.

## Реализация «Слепые ответы»: ограниченный первый срез
Один synthetic round с одним встроенным нейтральным RU/EN вопросом v1; ответы
раскрываются только после двух явных immutable submissions. До этого даже признак
отправки партнёра отсутствует в API. После завершения второго раунда пока нет.
Это не перенос всех 11 режимов, не ежедневный вопрос и не production-запуск.
[Контракт](../services/api/BLIND_ANSWERS.md), [проверки](BLIND_ANSWERS_EVIDENCE.md).
