# Общие текстовые воспоминания: bounded synthetic-срез

## Что получает пара
Любой участник подтверждённой активной пары может написать короткий заголовок,
текст и выбрать календарный день. До явного подтверждения публикации это только
приватный RAM-черновик. Опубликованная запись доступна обоим участникам текущей
пары. Лента показывает последние 50 созданных записей с авторством, датой события
и отдельным временем записи. Дата события не переводится в UTC.

Это первый текстовый срез общей хроники из Tan Ata `/talk/moments`, не перенос
«Дня за днём» из `/us`: дневник ответов обоих и его правила слепого раскрытия
остаются отдельной задачей. Записи не создаются из чата, слепых ответов, писем,
календаря или активности автоматически. Нет AI-интерпретации, presence или tracking.

## Контракт
- Независимый `enableSyntheticSharedMemories` opt-in, только loopback.
- GET `/v1/couples/:coupleId/memories?membership_epoch=N` возвращает
  `{ok:true,value:{memories:[Memory],limit:50}}`.
- POST на ту же коллекцию принимает только `command_id`, `membership_epoch`,
  `title`, `body`, `local_date`; JSON и совпадающий `Idempotency-Key` обязательны.
- Результат записи: `{ok:true,value:{memory,commandId,replay}}`, 201 при создании,
  200 при точном повторе. Memory содержит `id,coupleId,creatorId,membershipEpoch`,
  `title,body,localDate,createdAt`.
- Заголовок: общий NFC-нормализатор, 1–200 Unicode codepoints, до 800 UTF-8 bytes.
  Текст: NFC, нормализация CRLF/CR в LF, непустой, максимум 2000 codepoints;
  NUL и непарные surrogate запрещены. Текст не HTML и не Markdown renderer.
- День: строгий Gregorian YYYY-MM-DD (0001–9999), без timezone/UTC conversion.
- Порядок ленты: created_at DESC, id DESC. Нет pagination и полного архива.
- 400 invalid_request; 401 unauthenticated; 403 unavailable; 409 stale_membership
  либо idempotency_conflict; transient failures 503 без раскрытия содержимого.
- Ответы no-store; текст не попадает в URL, аналитику или уведомления.

## Авторизация и повтор
Каждое чтение, создание и replay проверяет свежую сессию, активную пару с двумя
активными участниками и membership epoch. Применяется общий порядок SQL locks,
согласованный с завершением пары. Чужая пара, бывший участник и закрытая пара
не получают запись или старый receipt. Receipt привязан к actor + commandId,
парам/epoch и полному нормализованному содержимому. Другой payload с тем же ID
конфликтует; новый ID может намеренно создать ещё одну похожую запись.

После неизвестного ACK клиент сохраняет исходную неизменяемую команду для явного
повтора. Новый черновик не подменяет retry и не стирается поздним ACK. Отмена
черновика не отменяет уже отправленную запись. Смена сессии, пользователя, пары
или epoch очищает RAM и блокирует старые callbacks. Список обновляется вручную.

## Честные ограничения
Нет редактирования/удаления, файлов/фото, поиска, экспорта, durable drafts,
фонового sync, push, read receipts или полного дневника Tan Ata.
Записи неизменяемы; ограничение сообщается перед публикацией.
Сервер хранит plaintext, это не E2EE. Существующее закрытие пары запрещает доступ,
но этот срез не определяет production-retention или судьбу архива после расставания.
Default App остаётся offline demo; connected runtime использует synthetic данные.
Native iOS/Android, два устройства и production readiness не подтверждены.
Проверки и статус: [SHARED_MEMORIES_EVIDENCE](SHARED_MEMORIES_EVIDENCE.md).
