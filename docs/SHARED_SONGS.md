# Наши песни с объяснениями: bounded synthetic-срез

## Сценарий
Участник активной тестовой пары указывает название песни и своими словами пишет,
почему она важна для пары. До отдельного подтверждения видимости партнёру это
приватный RAM-черновик. Публикация сохраняет название и объяснение для обоих.
Лента показывает до 50 последних добавленных песен с ID автора и временем записи.
Это самостоятельная коллекция, не разновидность общих воспоминаний и не копия
плейлиста Tan Ata. Автоматического импорта из чата, писем или активности нет.

## Контракт
- Независимый `enableSyntheticSharedSongs`, по умолчанию выключен; только loopback.
- GET `/v1/couples/:coupleId/songs?membership_epoch=N`:
  `{ok:true,value:{songs:[Song],limit:50}}`.
- POST той же коллекции: только `command_id,membership_epoch,title,explanation`.
  JSON и совпадающий `Idempotency-Key` обязательны. Неизвестные поля запрещены.
- Ответ: `{ok:true,value:{song,commandId,replay}}`; 201 при создании, 200 при replay.
  Song: `id,coupleId,creatorId,membershipEpoch,title,explanation,createdAt`.
- Название: NFC, 1–200 Unicode codepoints, не более 800 UTF-8 bytes;
  whitespace схлопывается, невидимые/управляющие символы заголовка запрещены.
- Объяснение: NFC, CRLF/CR → LF, непустое, до 2000 codepoints; NUL и непарные
  surrogate запрещены. Пробелы внутри объяснения сохраняются. Это обычный текст,
  не HTML/Markdown, не текст песни и не плеер.
- Порядок: created_at DESC, id DESC; ограниченный список, без pagination/архива.
- no-store; 400 invalid_request, 401 unauthenticated, 403 unavailable,
  409 stale_membership/idempotency_conflict, 503 temporarily_unavailable.

## Приватность, команды и жизненный цикл
Чтение, запись и replay требуют свежей сессии, активной пары с двумя активными
участниками и текущего epoch. SQL использует общий порядок блокировок закрытия
пары. Чужой/бывший участник не получает ни записи, ни старый receipt.
Actor+commandId уникальны; повтор обязан совпасть по паре, epoch и полному
нормализованному содержимому. Изменение title/explanation даёт конфликт.
Созданные записи неизменяемы, UPDATE/DELETE запрещены и на уровне БД.

Неизвестный ACK оставляет исходную неизменяемую команду для явного retry.
Новый черновик не меняет её и переживает поздний ACK, включая clear-and-retype.
Каждое изменение черновика снимает согласие. Очистка не отменяет отправленную
команду. Смена сессии/пользователя/пары/epoch очищает RAM и блокирует callbacks.
Обновление списка только вручную, без фонового сбора активности.

## Ограничения и следующий срез
Внешние музыкальные ссылки пока НЕ реализованы: нет URL-поля, открытия браузера,
fetch, preview, загрузок, streaming, lyrics или подключений музыкальных аккаунтов.
URL, набранный внутри обычного текста, не разбирается и не открывается.
Никаких утверждений о безопасности сайта или лицензировании трека.
Редактирование, удаление, ручной порядок и безопасные ссылки остаются в плане.
Нет durable drafts, фоновой синхронизации, поиска или полного плейлиста.
Default App остаётся offline demo; connected runtime только synthetic.
Сервер хранит plaintext, не E2EE. Закрытие пары прекращает доступ, но production
retention/экспорт/судьба архива после расставания этим срезом не определены.
Native/two-device и production-ready статус не подтверждены.
См. [проверки](SHARED_SONGS_EVIDENCE.md).
