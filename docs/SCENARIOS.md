# Сценарии и приёмка

Все пункты ниже целевые, пока не приняты как реализованные.
Общая матрица: RU/EN × iOS/Android; пользователь один / пара / бывший участник / чужая пара;
online / offline / reconnect; пусто / большая история; повторный запрос / конкурентное изменение.

## S01 Аккаунт и приглашение — P0
Создать аккаунт → подтвердить → создать пару → получить одноразовое приглашение → второй принимает.
Проверить просроченный/отозванный токен, повторное принятие, гонку двух получателей, уже полную пару,
попытку пользователя пригласить себя, logout и повторный вход. Никаких данных до принятия.
Сервер атомарно ограничивает активных участников двумя; ссылку не писать в логи.

## S02 Чат — P0
Написать → отправить → получить серверное подтверждение → получить на втором устройстве → прочитать.
Проверить потерянный ACK, offline, рестарт, повтор command_id, порядок при задержке событий,
блокировку бывшего участника, отсутствие дублей и восстановление истории. Детали CHAT.md.

## S03 Письмо — P0
Автор пишет/сохраняет черновик → выбирает получателя и время → подтверждает → письмо запечатано → открыто → ответ.
Черновик не виден партнёру. До release_at сервер не возвращает тело/вложения.
Проверить DST/смену зоны, несуществующую дату, час устройства в будущем, двойную отправку,
отмену своего будущего письма до открытия, отзыв членства до доставки и после открытия.
Отмена не удаляет уже прочитанную копию на устройстве партнёра; это ясно указать.

## S04 Сердце — P0
Центральная кнопка → подтверждение отправки → событие партнёру.
Никакого принудительного ответа. Проверить flood/cooldown, offline, reduce-motion и выключенный push.

## S05 Встреча — P0
Задать дату/часовой пояс → видеть countdown → изменить по expected_version → завершить разлуку.
Проверить пересечения, вчера/сегодня, разные зоны и отсутствие встречи. После встречи продукт остаётся полезен.

## S06 Разговоры — P1
Выбрать тему/вопрос → ответить или пропустить → явно открыть ответ партнёру.
Проверить, что личный ответ не раскрывается по чужому ID; режим взаимного открытия имеет отдельную настройку.
Редакционные вопросы не копировать из конкурентов; чувствительные темы добровольны.

## S07 Желания, дела и покупки — P1
Добавить → выбрать личное/общее → назначить себя или предложить партнёру → выполнить → архив.
Назначение партнёру требует принятия, не автоматически обещает его участие.
Два устройства меняют запись: конфликт виден, чужое изменение не теряется.

## S08 Календарь — P1
Создать общее событие → выбрать зону/напоминание → изменить/отменить.
Повторы/DST, отмена уведомления, quiet hours, отсутствие доступа к системному календарю.
Внешняя синхронизация только после запроса разрешения и отдельной реализации.

## S09 Альбом — P1
Выбор файла → проверка типа/размера → upload → подтверждение → общий просмотр/скачивание.
Чужой user/couple не скачивает даже при известном ключе. Отмена загрузки, дубликат, плохая сеть,
удаление объекта и производных миниатюр, EXIF/GPS по умолчанию очищены.

## S10 Поддержка и игры — P1
Настроение публикуется добровольно. Игровое приглашение можно отклонить.
Reconnect восстанавливает серверное состояние, не даёт второй ход; окончание не теряет результат.

## S11 Финансы — P2
См. FINANCE.md: расход, доля, корректировка, валюта, цели, удаление и экспорт. Без движения денег.

## S12 Выход/отвязка/удаление — P0
Logout очищает локальные приватные данные и push-токен устройства.
Отвязка атомарно прекращает новые чтения/записи/realtime и отменяет будущую доставку.
Удаление аккаунта показывает последствия для личных и общих данных; сервер фиксирует запрос и выполнение.
Загрузка экспорта требует свежей авторизации; файл ограничен сроком и доступом.
Проверить активные URL/кэш, два устройства, queued commands и повторное приглашение после отвязки.
Политика ранее совместного архива требует решения до запуска, не скрытой реализации.
