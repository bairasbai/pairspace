## Scope
One versioned bilingual neutral question, one immutable round per active pair epoch.
Explicit opening, reading and confirmed submission, RAM draft, immutable unknown-ACK
retry, server-side symmetric reveal. Before both submit, partner response is identical
whether the other participant submitted or not. No answered flag/presence/read receipt.
Participant snapshots, active pair, fresh provider session and epoch checked under
shared pair-close lock order. Own submitted text persists; partner text is not queried
before both submissions. SQL immutable guards and participant validation supplement API.

Current slice cannot edit/delete submitted answers or create another round. This is
not a production retention/quota policy. UI discloses these limits before consent.
No daily scheduler, notifications, AI, advice, psychological scores or other talk modes.
Server-readable plaintext, not E2EE. All fixtures and accounts are synthetic.
