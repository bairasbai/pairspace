## Explicit recipient opening, durable disclosure
After deadline, a filled slot is available metadata only until the recipient explicitly
POSTs open. First opening latches atomically; authenticated recipient rereads thereafter
remain available even if the server clock is corrected backwards. GET never opens or
writes. Empty/missed slots cannot latch. First-open clock and all membership/session
checks occur after locks. Exact open retries bind original command/slot and never open
another slot. Sender metadata never includes open state/time or read-receipt side effects;
author's independent own-body read is not authorized through the recipient latch.
Before first opening, clock policy still trusts the server; no monotonic-clock claim.
No notifications/outbox/read receipts are generated by opening.

Sender/recipient distinction is deliberate: the sender sees own prepared status and
can reread the immutable own body after release, independently of recipient opening.
The sender never receives recipient openedAt or any metadata change caused by that read.
The recipient's available-but-unopened GET remains metadata-only. A missed empty slot
cannot be opened or latched and cannot be filled late. Actual rollback tests first reach
a genuine database-clock deadline/open, then inject only the trusted test server clock.
