# Morning-letter notification privacy simulation

This internal-only slice concerns explicit morning_slots, not legacy immediate/scheduled letters.
It uses recipient notification category letter. It is NOT sending, opening, a queue or scheduler.
Existing schedule, release, numbering, prepared content, drafts, discussions, openings, arrival and
periods are unchanged. No event is generated by fill/draft-save. No message payload is copied.

## Exact trusted-time boundary
simulateMorningSlot(db,slotId) accepts only a slot UUID from trusted server/test composition;
no HTTP/mobile endpoint, actor impersonation, device/OS permission or provider exists.
Lock order: pair→slot→ordered current active members. Supported morning writes also serialize
on the pair. One actual SQL clock_timestamp is sampled after all locks, shared by release check,
quiet-policy evaluation and observation asOf. Application db.now/device values are not consulted.
The insertion guard separately enforces actual SQL release and observation timestamp>=release.

Before release the result is ONLY {ok:true,value:{state:'not_due',simulationOnly:true}}.
No observation is written, including for unavailable current scope. No content EXISTS, body,
prepared-version, preferences, private drafts, openings or previous observation is queried.
Filled, empty and draft-only slots cannot be distinguished by this operation before release.
Repeated early calls do not consume the slot: later first eligible processing can still proceed.
Even historical observations cannot be replayed before the actual release gate.

At/after release: current active pair, exact original membership epoch and both original members
must match. Invalid scope produces unavailable without reading content/preferences. Valid scope
reads only EXISTS morning_content; private drafts never imply readiness. Missing content becomes
missed, a terminal blocked simulation, not a missed-letter notification. Prepared content uses
latest own recipient prefs.letter + quiet hours; absent preferences mean disabled. No text/hash,
content version, opened/read timestamp or draft state is selected. Opened letters are deliberately
not treated specially, because this slice does not implement unread or delivery policy.

## Historical observation, never dispatch permission
One immutable row per slot stores identity scope, state simulation_eligible/simulation_blocked,
reason allowed|disabled|quiet_hours|missed|unavailable, asOf and preferenceVersion (NULL for
missed/unavailable). Exact concrete FK, shape and actual-release guards constrain persistence.
Concurrent processing deduplicates. Failed SQL rolls back, explicit same-ID retry is safe.
Replay preserves original reason/asOf with replay=true, simulationOnly=true,
historicalObservation=true, even after leave/settings changes, but only after release gating.
No shared outbox processed_at or other resource is changed. Missing slot returns not_found;
malformed UUID invalid_request. No result is exposed to either partner through a public endpoint.

Quiet-blocked remains a terminal simulation, not automatic quiet-end scheduling. No TTL is
invented. Future real dispatch freshness/unread/retention policy is unresolved and must be
specified separately. Future dispatch must recheck current pair/epoch/participants, availability,
latest prefs/quiet, current device/account permissions, dedupe/rate limits and freshness.
No native/two-device/production/E2EE/delivery/read-receipt claim follows from this slice.

## Verification scope
SQL-capture tests reject content/preferences/observation access before release and all body,
draft/opening reads throughout. Application future clocks cannot bypass actual SQL release.
Real release and held-lock tests share the existing genuine morning-boundary timeline using
isolated resources; existing assertions, per-test timeouts and clock semantics remain unchanged.
An additional full waiting interval is not substituted for a measured actual blocked-row test.
Early independent review precedes freeze; exact author and independent FULL remain mandatory.

Release comparison is SQL-native on the single sampled instant. Content EXISTS additionally
requires slot.release_at<=that same captured SQL timestamp. The exact UTC microsecond string is
persisted and returned as asOf; Date conversion is used only for minute-resolution quiet policy,
not release authority or stored precision. No second decision timestamp is introduced.
